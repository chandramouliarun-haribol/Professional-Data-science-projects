Feature Engineering¶

In [15]:
# 4 · Derive tenure, flags, usage aggregates
today = pd.Timestamp("today").normalize()

df["age_days"] = (today - df["subscription_date"]).dt.days
df["is_enterprise"] = (df["segment"] == "Enterprise").astype(int)

df["event_observed"] = df["canceled_date"].notna().astype(int)
df["duration"] = np.where(
    df["event_observed"] == 1,
    (df["canceled_date"] - df["subscription_date"]).dt.days,
    df["age_days"]
)

# extra features for deeper cuts
df["profile_total"] = df["twitter_profiles"] + df["facebook_profiles"]
df["tenure_bucket"] = pd.cut(
    df["age_days"], bins=[0,180,365,540,np.inf],
    labels=["0‑6m","6‑12m","12‑18m","18m+"]
)

This block creates analysis-ready features.

age_days converts subscription dates into numeric tenure, while is_enterprise turns the segment label into a 0-1 indicator for modelling.

event_observed and duration supply the required inputs for Kaplan-Meier survival analysis, capturing both churned and still-active accounts.

Additional columns—total social-profile count and broad tenure buckets—support usage-based slicing and easy-to-explain visual breakdowns.

What the KDE plot shows Each coloured curve is a kernel-density estimate of age_days (tenure) for one segment:

Blue – SMB

A KDE is just a smoothed histogram scaled so the total area = 1; the y-axis (“Density”) therefore indicates relative concentration of customers at each tenure value, not an absolute count.

The black dashed line at 400 days is a visual cue we added earlier to mark the “renewal-cliff” hypothesis.

Interpretation Broadly similar shapes All three segments have a fairly uniform tenure spread from ~0 to ~1 000 days, meaning no segment is dramatically younger or older overall.

Enterprise bump just left of the 400-day line The green curve has a small peak before the dashed line, then dips a bit more sharply than the others immediately after it. Implication: Enterprise accounts that survive the first year tend to leave in a noticeable cluster shortly after; this supports timing a retention email right before day 360–390.

SMB & Mid-Market peaks drift right The blue/orange curves peak closer to 500-600 days, suggesting their churn pressure builds later—perhaps because their contracts renew on longer cycles or they purchase upgrades before dropping off.

Tails beyond 1 000 days taper similarly, so ultra-loyal customers look alike across segments.

# 2. Power analysis – detect 2-pp churn reduction
import numpy as np
from statsmodels.stats.power import NormalIndPower

def proportion_effectsize(p1, p2):
    """Cohen h for two proportions."""
    return 2 * np.arcsin(np.sqrt(p1)) - 2 * np.arcsin(np.sqrt(p2))

baseline, uplift = 0.14, 0.02
es   = proportion_effectsize(baseline, baseline - uplift)
n    = NormalIndPower().solve_power(es, power=0.80, alpha=0.05,
                                    alternative="smaller")
print(f"Required N per arm ≈ {int(n):,}")

proportion_effectsize() converts “baseline churn 14 % vs. target churn 12 %” into Cohen’s h, the standard effect-size number a power calculator needs.

NormalIndPower().solve_power(...) then plugs that effect size into a power formula—asking, “How many customers per group will give an 80 % chance of detecting this 2-point drop at the 5 % significance level?”

The printout “Required N per arm ≈ 10” means you’d need roughly ten Enterprise customers in the email group and ten in the hold-out group to reliably see a 2-percentage-point churn reduction, given those assumptions.

# 3. Evaluate 30-day churn (difference-in-proportions test)
from statsmodels.stats.proportion import proportions_ztest 
df_ent["churn_30d"] = (df_ent["canceled_date"] <= df_ent["subscription_date"] + pd.Timedelta(days=30)).astype(int)

conv = df_ent.groupby("treatment")["churn_30d"].sum().values   # churners
tot  = df_ent.groupby("treatment")["churn_30d"].size().values  # totals

z_stat, p_val = proportions_ztest(conv, tot, alternative="larger")
print(f"p-value = {p_val:.4f}")

p-value = 0.1523

The code builds a 30-day churn flag, counts churners and total customers in the email-treatment and hold-out groups, then runs a two-proportion Z-test (proportions_ztest).

This test asks: “If the email had no real effect, how likely is it to observe a churn gap at least this large just by chance?”

The returned p-value is 0.1523, which is well above the common 0.05 significance threshold; therefore the data do not provide statistical evidence that the email lowered 30-day churn.

In practical terms, the experiment needs either a larger sample or a stronger creative to demonstrate a clear improvement.

# 4. CUPED variance reduction

df_ent["churn_prev_30d"] = (df_ent["canceled_date"] <= df_ent["subscription_date"] - pd.Timedelta(days=30)).astype(int)

avg_arr_per_logo = 2000   # replace with real revenue per customer
campaign_cost    = 5000
control_churn_rate   = df_ent.loc[df_ent.treatment == 0, "churn_30d"].mean()
treatment_churn_rate = df_ent.loc[df_ent.treatment == 1, "churn_30d"].mean()
incremental_arr = (control_churn_rate - treatment_churn_rate) * avg_arr_per_logo * len(df_ent)


cov = np.cov(df_ent["churn_30d"], df_ent["churn_prev_30d"])[0,1]
theta = cov / df_ent["churn_prev_30d"].var()
df_ent["cuped"] = df_ent["churn_30d"] - theta * df_ent["churn_prev_30d"]
#Decision rule
if (p < 0.05) and (incremental_arr - campaign_cost > 0):
    print(" Roll-out Enterprise email campaign")
else:
    print(" Hold – insufficient evidence or negative ROI")

 Roll-out Enterprise email campaign

What it is CUPED stands for Controlled Experiment Using Pre-Experiment Data. It’s a simple statistical trick that uses each user’s pre-campaign metric (e.g., their churn status or spend in a look-back window) to reduce variance in the post-campaign outcome you care about.

Why it helps The pre-period metric is usually correlated with the post-period metric. By subtracting a proportional amount of that pre-metric from every user’s post-metric, you strip out predictable “background” noise. Smaller variance ⇒ tighter confidence intervals ⇒ you need fewer customers (or detect smaller effects) for the same statistical power.

After the adjustment, the experiment is judged significant only if the p-value falls below 0.05 and the projected ARR gain exceeds the campaign cost; otherwise the rollout is deferred.
